# DriverPass

## Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?

The DriverPass project involved designing a system for a client who wanted to create an online platform to help students prepare for their driving tests. The client’s goal was to provide users with access to practice exams, schedule in-person driving lessons, track progress, and manage instructional resources. The system needed to support multiple user roles, including students, instructors, administrators, and management. It also required secure login functionality, appointment scheduling, reporting capabilities, and integration with updated DMV materials. Overall, the system was designed as a web-based application that combined learning tools with administrative management features.

---

## What did you do particularly well?

I believe I did well in translating the client interview into structured system requirements and diagrams. I created clear use case diagrams, activity diagrams, sequence diagrams, and class diagrams that accurately reflected the business processes described. I also focused on aligning functional requirements with user roles, ensuring that each feature directly supported a specific user need. This helped maintain consistency between the documentation and the overall system design.

---

## If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I were to revise one part of the project, I would further refine the nonfunctional requirements and system constraints. While the functional requirements were clearly defined, expanding on areas such as performance expectations, scalability, and security considerations would strengthen the overall design. In future revisions, I would include more measurable performance targets and clearer documentation of system limitations to make the design more production-ready.

---

## How did you interpret the user’s needs and implement them into your system design? Why is it so important to consider the user’s needs when designing?

I carefully reviewed the client interview and identified the core goals behind each requested feature. For example, the need to schedule lessons translated into appointment management functionality with role-based permissions, while the need for updated DMV materials translated into system requirements for content management and updates. Considering user needs is essential because system design should solve real problems. If the design does not reflect the user’s workflow and expectations, the system may technically function but fail to provide practical value.

---

## How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?

I approach software design in a structured and incremental manner. I begin by identifying functional and nonfunctional requirements, then define system constraints and user roles. Next, I create visual models such as use case diagrams, activity diagrams, sequence diagrams, and class diagrams to clarify system behavior and structure. These models allow me to validate logic before implementation. In future projects, I would continue using this model-driven approach while incorporating additional stakeholder feedback earlier in the design process to ensure alignment and reduce revision cycles.
